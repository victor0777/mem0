## Task 1: Batch Reconcile 성능 개선 (Backlog #1)

- **목표**: 117 chunks / 239초 → 30초 이내 (stretch), 60초 (realistic)
- **시도**:
  1. Codex (gpt-5.4)와 3라운드 constructive debate → ADR-001 작성
  2. 합의: batch_size 40 + ThreadPoolExecutor(3) + fallback 40→20
  3. 구현: `_embed_batch_or_split()`, `_batch_add_chunks()` 2-phase (concurrent embed → sequential write)
  4. 벤치마크 실행:
     - 40x3: 413 에러 (gateway max batch = 32 발견!)
     - 32x2: 455s, 64/117 성공 (gateway 500 과부하)
     - 32x1: 409s, 117/117 성공 (gateway 간헐적 500)
- **결과**: Gateway 불안정으로 공정한 비교 불가. 코드 개선은 완료:
  - Concurrent embedding 인프라 구축 (workers 파라미터로 조절 가능)
  - Fallback 로직 (32→16) 정상 작동 확인
  - Timing 로그로 병목 가시화 (embed 99.9%, write 0.1%)
  - Gateway batch limit 32 발견 → 이전 20에서 32로 60% 배치 증가
- **소요**: ~1시간
- **다음**:
  - Gateway 안정 시 32x2 벤치마크 재실행
  - Gateway 안정성 모니터링 (tech-debt 항목과 연계)
  - 원본 대비 batch_size 32 순차 성능 비교 (20 vs 32, 동일 조건)
